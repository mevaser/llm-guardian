The Security Problem

Modern applications increasingly connect LLMs to tools, workflows, data, and business logic. This creates a new attack surface:

  • Prompt injection
  • Policy bypass
  • Hidden instruction leakage
  • Unsafe tool use
  • Adversarial user behavior
  • Multi-turn manipulation
Before deploying an AI-powered feature, we need to know how it behaves under attack.

Project Goal

The goal is to build a tool that can:

  • Run controlled attacks against an AI target
  • Measure attack success
  • Track how many attempts were needed
  • Capture transcripts and trajectories
  • Generate a readable security report
  • Help developers harden the target
The goal is not to evaluate an agent for its own sake. The goal is to test how resilient an AI-powered application is against adversarial users.

Demo Target: Wizard Game Sandbox

The Wizard Game is a safe simulation of a real AI-powered application. It has:

  • Internal rules
  • Protected behavior
  • A target objective
  • Adversarial user attempts
  • Measurable success/failure outcomes
The Wizard demo provides a controlled environment for testing attack behavior without risking a real production system.

Red-Team Agent

The red-team agent does not represent the defended application. It represents an adversarial tester. It probes the target, adapts across attempts, and tries to find a successful bypass.

  • Autonomous attack attempts
  • Retry behavior
  • Prompt mutation / strategy changes
  • Trajectory logging
  • Controlled max attempts

Evaluation Layer

The evaluation layer is the measurement system behind the red-team lab. It tracks Attack Success Rate, Success@1, Success@3, Success@5, Success@6, Average Attempts, Refusals, Duplicates, Failure Taxonomy, and Attempt Transcript.

Important semantic clarification:

• Solved means the attack eventually succeeded within the allowed attempts.
• Success@1 means the attack succeeded immediately.
• Success@3 means the attack succeeded within the first three attempts.

In a security context, high attack success is bad for the target because it means the target is easier to break.

Report and Traceability

The lab does not only show a pass/fail score. It also provides:

  • Summary & Metrics
  • Case Results
  • Attempt Transcript
  • Markdown Report
  • Failure Cases
Every security finding should be explainable and traceable back to the actual attack attempts.

Why This Matters

Before connecting an LLM to CRM systems, ticketing systems, databases, internal documents, or workflow automation, teams need to test whether users can manipulate the AI into doing something unintended.

  • Safer AI deployments
  • Measurable red-team testing
  • Repeatable local lab
  • Better developer feedback loop
  • Preparation for OWASP LLM-style risks
